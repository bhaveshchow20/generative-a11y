## What automated tests prove

Core tests check which updates the runtime prepares and when. Adapter tests
check how framework events are translated. DOM and browser tests check page
structure and updates. None can confirm what a specific screen reader spoke or
what a person heard.

<Callout title="Evidence and testing note">

Test with real browsers and screen readers before release.

</Callout>

<span id="unsupported"></span>

## Unsupported by design

generative&#45;a11y does not replace semantic HTML, keyboard support, focus
management, visible status messages, or dialogs. It cannot read private
framework state, run remote code, guarantee screen&#45;reader speech, or guess
missing events from page text.

| Integration                                     | Evidence limit                                                            |
| ----------------------------------------------- | ------------------------------------------------------------------------- |
| [assistant-ui](/docs/integrations/assistant-ui) | No general retry or connection event                                      |
| [AI SDK](/docs/integrations/ai-sdk)             | The host must report retries that public framework state cannot establish |
| [AG-UI](/docs/integrations/ag-ui)               | No replay deduplication without a mandatory cursor                        |
| [CopilotKit](/docs/integrations/copilotkit)     | Uses the supported AG-UI path; there is no duplicate adapter package      |
