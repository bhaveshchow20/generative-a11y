## Send only the new text

Send response.started when a response begins. Each response.text.delta must
contain only the text that just arrived. Send response.completed to announce any
useful text still waiting. Send response.failed or response.interrupted to
discard that text.

```typescript title="Dispatch append-only response text"
runtime.dispatch({ type: "response.started", responseId: "r1" });
runtime.dispatch({
  type: "response.text.delta",
  responseId: "r1",
  delta: "First complete sentence. ",
});
runtime.dispatch({
  type: "response.text.delta",
  responseId: "r1",
  delta: "Second complete sentence.",
});
runtime.dispatch({ type: "response.completed", responseId: "r1" });
```

## Meaningful units, not tokens

Balanced mode waits for a complete sentence when possible. It can also prepare a
useful phrase after enough text arrives or a short delay. This avoids submitting
each token as its own announcement. See [core policy](/api/core/policy) to
change the text strategy or timing.

If your framework exposes accumulated text, use its supported adapter to derive
new text. A custom integration must distinguish an append from a replacement;
sending the full accumulated response as a delta repeats earlier content.
